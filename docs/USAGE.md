# 使用说明

## 1. 选哪种用法

| 你想要的 | 用法 | 说明 |
| --- | --- | --- |
| 问一个问题、读懂一篇论文、弄清一个概念，希望回答有依据、流程不被模型左右 | **独立使用**（`teacher.py chat` / `serve`） | Teacher 自己驱动模型；要不要反问、查什么、答案能不能显示，都由程序规则决定 |
| 自己动手练：设计算法、写正确性或复杂度论证、推导损失梯度，只要别人检查每一步 | **独立使用的练习模式**（`/coach 题目`） | 练习中屏幕上不出现任何模型写的文字，只有固定句子和你自己的原话 |
| 你已经在 Codex / Claude Code 里做长时间研究，需要它上网、跑代码、改笔记 | **附着使用**（安装技能） | agent 用自己的工具，但框定问题和最终答案要过同一套检查；这是行为约束，不是边界 |

两种用法不等价：只有独立使用能保证“模型只用于回答问题，流程由程序决定”。

## 2. 第一次运行（独立使用）

```sh
cd payload/teacher/scripts          # 安装成技能后是 <技能目录>/teacher/scripts
python3 teacher.py setup --base-url https://你的地址/v1 --model 模型名 --read-root ~/笔记目录 --read-root ~/论文目录
export TH_API_KEY=你的密钥            # 或 python3 teacher.py setup --api-key-stdin（写入仅本人可读的密钥文件）
python3 teacher.py index ~/笔记目录    # 先看会索引多少文件，再按提示加 --apply 执行
python3 teacher.py chat
```

`--network on|off` 控制能否查 arXiv 和白名单网站（默认开启）。`--model-guard on` 会在每个回答前多请一次独立守卫（只能否决，更慢）。

## 3. 直接问就行

你不需要先把问题说清楚，随便说：

```
你> 我的模型效果不好，是不是该换个方法
先确认一件事：你的问题可以有几种理解，它们会把回答带向不同方向。
1) 其实想先定位模型效果差的原因，再判断是否需要换方法（目标不同）
2) 其实想比较替换方法的预期收益、成本与适用条件（产出形式不同）
回复编号即可；直接回车按 1)；都不是就直接补一句。
```

Teacher 什么时候会问你：只有几种理解会导向**不同的工作**、而查你自己的资料也分辨不出来时，才问**一次**选择题；
否则直接按最可能的理解回答，并在开头写“我的理解：…”，想换就 `/switch 2`。事实上的不确定它会去查或承认不知道，不会拿来问你。

## 4. 怎么读一个回答

```
暂按：用中文回答、按常规深度
结论：……（不超过 240 字）
把握：中

要点
1. ……
   〔依据：来源引用（未复现）｜等级：有限范围经验证据｜强度：有界结论〕[E1]
   原文：“……”          ← 这句话逐字节出现在 E1 里
   不能推出：……
为什么（逐步剖析）
- 关键一步  动机：…｜适用边界：…｜失效时：…
还不知道 / 尚未完成
可以接着核验
来源：E1 notes/a.md#标题
你可能接着想问（输入 /ask 编号）
〔本轮｜调查 3/4 步，执行 7 项操作｜来源片段 2 条、被引用 2 条｜原文核验 2/2｜仅凭推理 0 条｜未展示候选 0 条〕
```

- **依据**告诉你这条靠什么：来源引用、本地执行核验、你提供的材料，或“仅凭推理（未核验）”。
- **等级**只能和强度相称：数值证据撑不起全称结论；网上或笔记里的一句话永远不能标成“形式化验证”。
- **最后一行指标**全由程序计算：查了几步、引用了几条、原文核验通过几条、多少要点只是推理、有多少候选没展示。
- 检查保证的是“每条话说清了自己依据什么”，不保证内容一定正确。

`/more 1` 看 E1 的原文片段；`/ask 1` 接着问建议的问题。

## 5. 它怎么调研

每个问题，Teacher 都会**先**查你已经归档的研究资产和已索引的笔记/论文，再让模型决定还要查什么（本地片段、arXiv、白名单网页、配置里声明过的命令）。
模型只能“点名”这些只读操作，由 Teacher 执行并计数；搜索先给候选（路径、标题、短摘要），需要时才读原文，每次都重新打开磁盘上的当前文件。
论文理解、方法比较、研究问题、复现、文献调研这几类问题，没有找到来源就不会假装找到，而是在“还不知道”里写明缺口。

## 6. 保留有价值的东西

每个通过检查的回答都会自动产生归档候选：有依据的结论、引用过的来源、失败的检查、还没解决的问题。只凭推理的内容不会成为候选。

`/archive` 会列出候选，你只需回一个数字：`1` 只归档已核验的（默认）、`2` 全部、`3` 都不要。退出时如果有已核验的候选，会提示一次。
归档后的内容会在下一次提问时被优先查到，并进入 Teacher 自动维护的“核心认知”。

## 7. 把一串问题升格为研究目标

连续几次在同一类问题上打转时，Teacher 会主动提议。输入 `/project`：它根据你前面的提问起草六个字段（陈述、领域、结论范围、前提、证据标准、完成标准），你看一眼，`/confirm` 确认（或先 `/set 字段 新内容` 再确认）。
持续研究的结论、评审、完成检查用 `teacher.py engine -- …`（见 `payload/teacher/references/operations.md`）；需要长期保存、地图、交接包时用 `cs-ai-research-solve` 技能。

## 8. 练习模式

```
你> /coach 证明：对长度为 n 的有序数组做二分查找，最坏情况下比较次数为 O(log n)。
你> 每次比较后搜索区间至少减半，所以 k 次比较后区间长度不超过 n/2^k。
```

Coach 只检查你写的这一步：成立、不成立、依据不足或说不清，以及第一个能确定的错误类别，并引用你的原话。它不给答案、不补决定性的步骤、不替你换路线。
`/route` 看自己的路线；`/hint` 在已有记录的错误、且你又提交过新尝试后，给一次不超过 120 字的受守卫提示（明确标注不属于 HARD_LOCK 保证）；
`/idea 步骤编号 内容` 写一个连到某一步的探索性想法；`/incubate targeted_question 1 2` 围绕你自己的两步生成一个固定模板的追问；
`/conclude 内容` 提交结论；`/done` 做严格完成检查，`/done lenient` 用宽松标准；`/exit` 封存。练习中不能用回答模式的命令；退出的题目也不会在回答模式里被直接解答。

## 9. 附着使用

安装：`python3 install.py --agent claude --yes`（或 `--agent codex`、`--agent generic --target-root 目录`），然后新开一个 agent 会话，说 `$teacher 你的问题`。
agent 会按 `teacher` 技能的规则先框定问题，用 `teacher.py frame-check` 判断要不要问你；调研后把答案交给 `teacher.py check-answer`，并原样给你它渲染的文字。
`check-answer` 会重新读取每个引用片段的本地文件（网络开启时也会重新抓取网页），核对不上的片段直接丢弃；答案末尾会写明多少片段由 Teacher 亲自核对过、多少只能采信 agent。

## 10. 本地网页

`python3 teacher.py serve` 在 127.0.0.1 上启动，终端里打印带一次性令牌的地址。网页提交与命令行走同一套流程和检查，练习命令也能用。重启后旧链接失效。
