# 安全模型

## 控制方向

先确立谁控制谁，因为其余一切都是在回答这个问题。

在提示词式部署里，**模型是操作方**：它读了文档，然后自己决定做什么、自己输出给人。
独立模式把这个关系反转：

| | 提示词式部署 | Teacher 独立模式 |
| --- | --- | --- |
| 谁发起回合 | 模型 | **harness**（`Teacher.ask`、`Coach.step`） |
| 谁决定模型何时被调用、问它什么 | 模型 | **harness**：固定的四个问题点 |
| 谁决定要不要反问用户 | 模型 | **harness**：`need.decide` 的规则 |
| 谁执行检索与命令 | 模型 | **harness**（`Broker`），模型只能点名封闭操作 |
| 谁决定答案能否显示 | 模型 | **答案门**（`answer.validate_answer`） |
| 谁写用户看到的文字 | 模型 | **确定性渲染器**，模型文字只进带标注的槽位 |

具体到代码，控制权体现在这些地方：

1. **harness 拥有循环。** 请求 → 输入门 → 需求框定 → harness 先查资产 → 有界调研轮 → 作答 → 答案门 →
   可选守卫 → 渲染 → 提交。模型在整条链里没有一步可以选择流程分支。
2. **模型没有能力，只有请求。** 后端协议里的每个方法都只回答一个封闭问题；没有任何方法能“做事”。
   后端进程本身没有工具：它只收到一个数据包，返回一个 JSON。
3. **`Broker` 拥有全部权限。** 它按配置给出的读取根、声明命令与网络策略执行，自己不扩大任何一项；
   模型给不出命令行、路径根或域名白名单。
4. **输入被拒时模型根本不被调用。** 输入门在第一次后端调用之前运行。

**仍然做不到的**：如果宿主是一个拥有通用工具权限的 agent（附着模式），它可以绕过 harness 直接写文字或文件。
这不是本包能防止的——只能让它**可见**：存储有哈希链，包有校验和。

## 承诺边界

### 三种用法，三种承诺

**1. 附着模式（不承诺控制，只承诺同一套检查）**

宿主 agent 读了 Skill，用自己的工具调研，再把框定交给 `frame-check`、把答案交给 `check-answer`。
这两个命令执行与独立模式**完全相同**的确定性规则，并在答案里如实标注：宿主给出的证据片段中，
哪些由 harness 在原位置重新读到（`verified`），哪些 harness 无法核对（`declared`）。
但宿主仍可能不走这两个命令，直接在对话里输出。**这是行为约束，不是边界。**

**2. 命令行（可承诺：拒绝时无副作用）**

`teacher.py` 与 `th.cli` 上的每一个写入都经过门禁。可承诺的性质是：

> 不合规的写入被拒绝，且被拒绝时 `authority` 与 `execution` 两个 head 都保持原值。

这条性质由三件事共同保证：所有结构性改动都经过 `Store.transact()`（比较并交换、提交后回读校验）；
门禁在事务之外运行，被拒绝的操作根本没有进入写入；记录的效果（`record_effect`）是推导出来的，不由任何地方直接赋值。

**3. 独立模式（可承诺：数据流性质）**

`teacher.py chat / ask / serve`。可承诺的性质分两条路径：

> **回答路径**：模型的输出不能选择流程分支、不能改变状态（除了经校验的封闭字段）、不能直接到达屏幕；
> 屏幕上每一段模型撰写的文字都位于带标注的槽位里，且所在答案已经通过答案门。
>
> **练习路径（HARD_LOCK）**：在一次练习回合中，模型撰写的文字没有任何通往屏幕的路径；
> 唯一例外是经资格判定与守卫、明确标注“本提示不属于 HARD_LOCK 的绝对输出保证”的一次性提示。

这些性质由以下机制共同保证，每一项都可以在代码中核对：

| 机制 | 位置 | 作用 |
| --- | --- | --- |
| 封闭键集 | `need.validate_frame_draft`、`answer.validate_plan`、`answer.validate_answer`、`coach._closed` | 多一个键就拒绝 |
| 封闭枚举 | `constants` | 每个取值必须在词表内 |
| 读法锚定 | `need.validate_frame_draft` | 每种理解必须逐字引用用户原话 |
| 引文逐字节校验 | `answer.validate_answer` | 自称的原文必须出现在所引片段里 |
| 依据—证据一致 | 同上 | 来源类依据只能引来源片段，执行类只能引执行结果 |
| 强度—等级表 | `constants.MINIMUM_GRADE_BY_STRENGTH` | 结论不能强于证据 |
| 必写未知项 | 同上 | 证据不完整时必须声明未知 |
| 长度上限 | 同上与渲染器 `_slot` | 简短由程序保证，渲染器再查一次 |
| 确定性渲染器 | `render.Renderer` | 用户可见文本的唯一写者 |
| 固定失败串 | `render.render_ask_failure`、`coach.SAFE_COACH_FAILURE` | 失败只产出固定的话与封闭计数 |
| 失败码白名单 | `engine.safe_code` | 异常信息不越过边界 |
| 封闭操作词表 | `broker.OPERATIONS` | 全为只读；没有会改动的操作 |
| 参数键封闭 | `broker.validate_request` | 多一个键就拒绝，不忽略 |
| 路径限制 | `broker.confine` | `resolve()` 后判包含，符号链接指出去也会被拒 |
| 命令只能点名 | `broker._run_declared` | 命令来自配置清单 |
| 网络策略 | `web.host_allowed`、`broker.network` | 关闭时一律拒绝；开启时只访问白名单域名 |
| 原始输出不上屏 | `broker` | 命令输出只以有界片段进入模型数据包 |
| 界面提交走同一套门禁 | `server/app.py` 的 `/api/submit` | 浏览器没有跳过门禁的路径 |
| 令牌能力分离 | 同文件 | 每次请求校验令牌，越权与不存在同响应 |

## 绝对承诺的确切范围

上面的断言是**数据流性质**，不是语义性质。明确它不是：

- 它**不**声称答案内容正确。答案门证明的是“每条结论说清了自己依据什么、没有强于证据、引文确实在来源里”，
  而不是“结论为真”。`semantic_correctness_proven` 永远为 false。
- 它**不**声称能识别任意形式的语义伪装：换一种记号、翻译、编码、逐步诱导。
  判断“这段任意表述里是否夹带了不该给的东西”需要解决守卫本身想防的分类问题。
- 它**不**覆盖附着模式，也**不**覆盖在本地界面之外完成的任何工作。**不要把这几种用法描述成等价的。**

因此做法是：把可证明的部分收窄到能证明的程度，并把它说清楚；剩下的部分用
“结构化自报 + 独立复核 + 事后可检”来处理，而不是假装它被防住了。

## 信任边界

- 存储（SQLite）对框定、回答、证据片段、候选、目标、结论、评审、评估与收据是权威的。
- **后端输出即使满足 schema 也不可信。** schema 校验只排除形状错误；答案门只排除可判定的违规。
- **守卫输出同样不可信。** 它可以否决，但它的批准不能让一段被答案门拒绝的文字变得可以显示。
- **检索到的文本与网页内容是不可信数据。** 它们只进模型数据包；上屏的只有经逐字节核对的引文，
  以及用户主动 `/more` 查看的原文片段（标注为原文）。
- 被拒绝的候选不被持久化。

## 威胁

需要防的包括：模糊或自相矛盾的请求、伪造的引文、编造的来源编号、强于证据的结论、把“代码跑通”当作结论成立、
把推理当作已证实、隐瞒调查没做完、直接索要答案（练习模式）、指令覆盖、伪造退出、角色扮演、翻译与编码、
逐步累积的诱导、检索内容里夹带的指令、越权的操作请求、越界路径、未声明命令、未授权网络访问、
过期的评估确认、畸形结构化输出、后端不可用、数据库锁、进程重启。

## 失败行为

后端超时、不可用、返回畸形结构、答案门两次拒绝、守卫否决、数据库失败——以上任何一种，界面都只渲染
固定的话，外加封闭计数（调查了几步、执行了几项操作、取得几条片段）。
只持久化安全的状态：token 形状的码、SHA-256 摘要与封闭风险码。
**不**持久化被拒绝的候选正文、推理、提示、子进程输出或原始工具输出。

## 密钥与配置

- API 密钥不进入包，也不进入配置文件。它来自环境变量 `TH_API_KEY`，或 `setup --api-key-stdin` 写入的、
  仅属主可读的独立密钥文件；传给后端子进程的是文件路径，不是密钥本身。
- 配置与状态放在平台用户目录，不在包内。

## 本地暴露与能力

- 绑定 `127.0.0.1`；端口默认随机；启动时随机生成令牌。令牌只在进程内存里，**重启即让此前所有链接失效**。
- 令牌经 URL fragment 传给浏览器，读入内存后立即清除；每次请求校验 `X-Teacher-Harness-Token`。
- 越权请求与指向不存在资源的请求返回**相同的** `403`，且在查找任何对象之前返回。
- **不支持**远程绑定、CORS、持久令牌或联网多用户账号。若要联网部署，需要账号、可认证身份、撤销机制与审计授权。
